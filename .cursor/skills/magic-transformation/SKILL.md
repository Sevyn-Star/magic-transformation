# 魔法变身

Magic Transformation.

先定一条主风格，再按段拼布局，最后只加少数特效和动画。每一页还要过「页面标准」和「裁切」：元素齐、画框固定、字号和间距成套。页面要能读、能点，关了动效仍然完整。

风格管看起来像什么。布局管每一段怎么分栏。特效管表面。动画管怎么动。

## 何时使用

- 用户要做网页、改版、选模板气质、指定版式、特效或动画。
- 用户把某一条轴或全部轴设为「随机」。
- 用户要测速，或页面做完需要验收加载和交互。

只问清单时，列出可选 id 后停止，不要动手做页面。

## 先做什么

1. 记下用户已经点名的 id。四个轴都可以单独写成「随机」。说全部随机、随便或换一组，等于四条轴都是随机。
2. 没点名、也没选随机、但描述对得上某一条布局、特效或动画时，采用那个 id，并在配方里写明是推断。主风格不靠描述推断。
3. 随机的轴按下面的种子公式抽。不要用默认配方填随机的空位，也不要按条目里的「混搭」挑顺手的组合。
4. 只打开被选中的条目。不要把四份目录全文读进同一次实现。
5. 先写出配方。没有成文规范时，再做完整一页。有成文规范时，按下一节把要做的页一次做完。

目录：

给人看的总览，含全部 id 和一句说明，在仓库根目录的 [README.md](../../../README.md)。

- 风格：[references/styles.md](references/styles.md)
- 样式布局：[references/layouts.md](references/layouts.md)
- 特效：[references/effects.md](references/effects.md)
- 动画：[references/motion.md](references/motion.md)
- 模板：[references/templates.md](references/templates.md)。选定主风格后只打开表里同一行，并在配方里写下那个链接。

条目 id 稳定，例如 `style.editorial`、`layout.split`、`fx.grain`、`motion.mask-reveal`。回复和代码注释用这些 id。

每条目录都按同一份操作说明来读：开头是何时使用，中间是怎么做，然后是不要做什么，「细化」是必须遵守的尺寸、状态和缺内容时的做法。

## 有成文规范时

用户给了页面清单、目录结构，或写明每一页必须有哪些块时，先读那份规范，再做设计。规范决定有哪些页、每页有哪些块、什么情况下不建页。风格、特效和动画只改变这些块怎么呈现。

主风格按「随机」里的风格规则抽，不看这一站像哪一类。读完规范后，把要做的页一次做完，不要停在首页。同一套主风格、点缀、特效和动画用在所有页上。回复里写出这次的主风格 id、种子和下标。

1. 读规范，逐页列出块。规范允许省略的页单独写原因：不够门槛、栏目未就绪、没有数据。这些页不要建，也不要用别的布局的示例内容补上。
2. 先按「首页篇幅」写出首页从首屏到页脚的段序，再做页。每一块对上一个布局，装规范里的内容，并满足「页面标准」和「裁切」。规范的块比 3 到 7 多，就全部保留。相邻段仍然不重复。某一块只有一两句、撑不起这一段时，按「补材料」补足，不把首页收成一屏。
3. 布局条目里的题材只在规范自己要求这种页时使用。职位、找不到、订阅、预约、等候、房源、菜谱、行程、价目板，都是各自页面的题材。不要为了填满段数，把它们贴到别的页上。
4. 空状态写这一页自己的事。职位列表写「现在没有开放的职位」，只属于招聘页。名录、城市、行业、文章页没有条目时，写规范允许的那句空状态，不改口成别的布局的句子。
5. 规范没写的数字、人名、评价、价格和地址仍然不编。空着就空着。规范要求展开的页按它的块做完。

交稿前每一页都过下面这几条。有一条没过，就改完再交：

- 画框被写成自动高度，或同一组卡片的高低跟着原图走。
- 裁切切掉了主体，或用绘画、拼贴、操场、车站、球场来代表一座城或一门手艺。
- 第一屏的下拉、单选或多选还是系统默认样式。
- 首页少于 9 层，或导航、页脚没有单独算层。
- 左右对开留下一块没有内容的空底，或导航直接浮在照片上。
- 很多入口做成同样大小的大图加同样长的说明，排成一堵墙。入口要有层次：少数几张大图，其余用小图或文字。
- 相邻几节只是换了底色，标题、正文和间距没有拉开。

用户之后说换风格、不合适、再换一个：丢掉这次的主风格，按随机再抽一个没用过的，特效和动画若不是用户点名的也一起重抽。已做的页改成新风格。内容仍是规范里的内容，不改成另一份文档。

随机布局遇到成文规范时，只给这一页的块抽「怎么分栏」，不抽「加一段什么题材」。抽中的布局和这一块的题材冲突，就丢弃重抽。规范已经写满各段时，不再增加段。

## 默认

用户没指定布局、特效、动画，也没有成文规范时，用下表的这三列，并写清可以替换的项。不要自己堆满。表里的主风格一列不采用。主风格每次都按「随机」抽取。有成文规范时，不用这张表决定有哪些段。

| 页面用途 | 主风格 | 布局（从上到下） | 特效 | 动画 |
|----------|--------|------------------|------|------|
| 作品集、工作室 | `style.editorial` | `layout.cover-index`、`layout.magazine`、`layout.gallery`、`layout.quote-break`、`layout.footer-heavy` | `fx.grain` | `motion.mask-reveal`、`motion.word-stagger` |
| 产品发布 | `style.product` | `layout.center-stage`、`layout.feature-rows`、`layout.bento`、`layout.steps`、`layout.pricing` | `fx.glow` | `motion.fade-rise`、`motion.shared-element` |
| 商店 | `style.commerce` | `layout.split`、`layout.cards`、`layout.carousel-row`、`layout.comparison`、`layout.faq` | `fx.paper` | `motion.hover-swap`、`motion.fade-rise` |
| 餐饮、空间 | `style.hospitality` | `layout.header-stack`、`layout.split`、`layout.index-rows`、`layout.form-split`、`layout.footer-heavy` | `fx.grain` | `motion.mask-reveal`、`motion.parallax` |
| 技术、开发者 | `style.terminal` | `layout.sticky-side`、`layout.steps`、`layout.comparison`、`layout.faq` | `fx.scan` | `motion.fade-rise`、`motion.underline-draw` |

数量上限：

- 主风格 1 个。点缀最多 1 个，而且只改一件事：标题字体、一种强调色，或一种栏宽。
- 布局一段一个。没指定段数、也没有成文规范时，段数随机，取 3 到 7，相邻段不重复。有成文规范时，段数等于规范里的块数。
- 特效最多 3 个，高成本最多 1 个。高成本是 `fx.liquid`、`fx.glass`、`fx.goo`。
- 动画最多 4 个。`motion.pin-story`、`motion.horizontal`、`motion.image-sequence`、`motion.smooth-scroll`、`motion.infinite-columns` 里最多留 1 个。

风格和布局都写了页面顺序时，栏数和滚动骨架听布局的，字体、色彩和图像气质听风格的。

## 随机

「随机」和具体 id 并列。点了哪一条轴，就只随机那一条。主风格例外：只要用户没有点名某一个 `style.*`，主风格就一律随机，不看页面用途，也不用默认表里的那一列。用户说换风格，等于再随机一次主风格，并把已做的页改成新风格。

每次都要重新掷。禁止复用上一轮的主风格，也禁止因为「好配」改掉掷出来的 id。抽到的主风格若与上一轮相同，或与本站已经用过的主风格相同，就丢弃，种子加 1 再抽，直到不同。连续 20 次仍相同，才保留这次抽中的，并在配方里写明池子已经转完。

种子用本地时间 `YYYYMMDDHHMMSS` 的整数。同一次对话里再次随机时，在后面加上第几次，例如第一次 `20261113111600`，第二次 `202611131116002`。配方里写下种子。

池子顺序就是文件里 `## id` 出现的顺序。先读出完整列表，再取下标。不要按喜好重排。

```
state = 种子
取一次：
  state = (state * 1103515245 + 12345) mod 2147483648
  下标 = state mod 池子长度
  抽中 = 池子[下标]
```

每抽一次都更新 state。抽中的 id 从这一轮池子里移除。

已经指定的轴不掷。随机的轴按风格、布局、特效、动画的顺序掷。后掷的要躲开已经冲突的 id。

- 风格：从全部 `style.*` 里均匀抽 1 个。先把上一轮和本站已经用过的主风格移出这一轮池子，再抽。池子被移空时才放回，并在配方里写明。再掷一次，若 `state mod 4` 等于 0，再抽 1 个不同的做点缀；否则点缀为无。点缀若和主风格落在互斥对里，点缀改为无。
- 布局：没有成文规范时，段数 = `3 + (这次 state mod 5)`，得到 3 到 7。然后按段数抽。相邻两段相同就丢弃重抽。用户已经指定的段保持不变。有成文规范时，段数等于规范里的块数，只为这些块抽布局，抽到题材冲突就丢弃重抽。
- 特效：个数 = `1 + (这次 state mod 3)`，得到 1 到 3。高成本和低成本概率相同。抽到第二个高成本，或触发纹理互斥时，丢弃重抽。
- 动画：个数 = `2 + (这次 state mod 3)`，得到 2 到 4。撞上滚动类互斥、平滑滚动对吸附、或和已选布局重复实现时，丢弃重抽。同一标题不叠两种文字动画，后抽到的文字动画丢弃重抽。

某一抽连续 20 次仍冲突，就放弃这个名额，并在配方里写明少了一个。不要用手挑一个看起来更合适的顶上。

和上一轮随机配方完全相同就把种子加 1，整组重掷，最多 5 次。

配方里写出种子、每一抽的下标和抽中的 id。

## 互斥

碰到下面的组合就删掉后写的那个，并在配方里说明原因。

- `fx.liquid`、`fx.glass`、`fx.goo`、`fx.displace` 之间只留先被点名的一个。
- `fx.grain`、`fx.scan`、`fx.compress` 最多留两个。
- `fx.duotone` 与 `fx.split-tone` 只留先被点名的一个。
- `motion.smooth-scroll` 与 `motion.snap` 只留一个。
- `motion.pin-story`、`motion.horizontal`、`motion.image-sequence`、`motion.smooth-scroll`、`motion.infinite-columns`、`motion.video-scrub` 只留一个。
- `motion.image-sequence` 不再加高成本特效。
- `motion.coverflow` 不再与 `motion.carousel`、`motion.horizontal` 一起做横移。
- `layout.pinned-media` 不再加 `motion.pin-story`。
- `layout.carousel-row` 与 `motion.horizontal`、`motion.coverflow` 只实现一次横移。
- `layout.stack` 与 `motion.card-stack` 只实现一次层叠。
- `layout.masonry` 不加 `motion.parallax`。
- `layout.video-hero` 若同时选了 `motion.video-scrub`，全页只这一段影像跟滚动走。
- `style.brutalist` 与 `style.luxury`、`style.brutalist` 与 `style.neumorphic`、`style.brutalist` 与 `style.grunge`、`style.terminal` 与 `style.hospitality`、`style.playful` 与 `style.archive`、`style.japandi` 与 `style.cyber`、`style.pixel` 与 `style.luxury`：只留一个做主风格。另一个若被点名，降成点缀；两个都想做主风格时，留用户先提到的那个。
- `fx.cursor-shape` 在触控和键盘上不显示，光标动画也不在这些设备上启动。

## 配方

实现前先写出这份配方，做完后它仍然成立：

```
配方
- 内容清单：没有成文规范就写「无」。有的话，逐页列出块；按规范省略的页写原因
- 参考模板：本次打开的链接。没有对上就写通用骨架那一行
- 主风格：
- 点缀：无，或一个 id 加它只改的那一件事
- 布局：从上到下每一段的 id，并写它装的是哪一块。段数是随机时写明掷出的数字
- 特效：
- 动画：
- 搭配理由：这些选择为什么能放在一起
- 随机：哪些轴是随机的；种子；每一抽的下标和抽中的 id。不是随机就写「无」
- 页面顺序：导航、首屏、中段、结尾、页脚。多页时按内容清单的页序
- 本页必须有：导航、一个 H1、首屏主动作、规范里的块、每个图的比例和焦点、字号阶梯、间距阶梯、结尾下一步、页脚
- 首页篇幅：从第 1 层导航编号到最后一层页脚，不少于 9 层；每一层的布局和内容；哪些层是上网补的，来源是什么
- 静态第一帧：关掉 JavaScript 和动效后仍能读到的内容
- 减少动效：prefers-reduced-motion 下直接呈现的终态
- 性能预算：高成本项数量、是否使用 WebGL、图片策略。图片策略写哪些块要图、站内路径和来源；这一页不需要图就写「无」
- 背景：纹理或表面的站内路径和来源；整页只用纯色就写「纯色」
- 这次不做：被互斥规则拿掉的项，以及因为题材冲突丢掉的布局
```

没有成文规范时，按布局清单从上到下做完整一页。有成文规范时，按内容清单把要做的页一次做完，全站用同一套主风格。每一块用它的布局来装规范里的内容，同时满足下面的「页面标准」。不要把布局条目里的示例题材装进这一页。导航、结尾动作和页脚都要在。段与段的阅读顺序不断。图片按「裁切」放进固定画框。没有真实客户、员工或合作品牌时，不放头像墙、评价和标志墙。

## 页面标准

每一页先写出「本页必须有」，再写样式。内容规范决定写什么。这一节决定这些东西必须以设计过的元素出现，而不是把标题、段落和原图堆上去。

本页必须有：

1. 导航，能看出当前页。
2. 全页一个 H1，说清这一页是什么。
3. 这一页有主动作时，第一屏里就有这一个主动作。第一屏不再并列第二个同样醒目的按钮。
4. 内容规范要求的每一块：一个节标题、一句引导，然后才是列表、卡片或正文。节与节之间的距离至少是节内距离的两倍。
5. 图：每个角色先定一个比例和焦点，再放图。规则在「裁切」。
6. 字号阶梯，全页最多五档：展示、标题、节标题、正文、辅助。正文 16px 到 18px，行高 1.5 到 1.7，行长大约 60 到 75 个字。辅助信息不小于 13px。不用浏览器默认的标题大小。
7. 间距走 8px 的倍数：8、16、24、32、48、64、96。卡片内边距全页一种。控件高 44px 或 48px，全页一种，圆角和描边也全页一种。
8. 颜色只有这些角色：页面底、表面、正文、辅助字、一种强调、焦点环。不要给相邻的三节各换一种底色来假装有层次。
9. 结尾有一个下一步，然后是页脚。

对齐到同一套栏。没有布局条目要求居中时，节的左缘对齐。卡片在同一行里顶边对齐，图框等高。

## 设计完成度

写代码之前先写一版设计稿，再对照这一节。设计稿要有：四到六个颜色的色值、最多两套字体和它们各自的用途、第一层内容怎么构图、这一页唯一让人记住的一件事。设计稿如果换成任何别的网站也成立，就改到和这一页的题材绑在一起，再写代码。构图先打开 [references/templates.md](references/templates.md) 里和这次主风格同一行的模板，看它的 [example.html](https://github.com/nexu-io/open-design/blob/main/design-templates/web-prototype/example.html) 或该行自己的整页。通用段落骨架在 [layouts.md](https://github.com/nexu-io/open-design/blob/main/design-templates/web-prototype/references/layouts.md)。不搬模板里的文案、品牌和色值。

字体：展示字和正文字可以是同一套，也可以是两套，两套必须分得开。展示字大约是正文的 3 到 5 倍，字距略紧，行高接近 1。正文行长不超过 75 个字。不要只把标题里的一个词换成另一种颜色或斜体。不要把栏目标签写成全大写。标签只有在它真的说明下一行是什么时才出现。

构图：留白是排出来的，不是没填满。左右对开时，两栏共用一条底边，字的一侧排到和图片同一条底，不留一块没有内容的空底。导航叠在照片上时，背后要有实色条或遮罩，字能读清。一张照片只留主体，电线、天空和无关招牌不占掉画面。

一层只讲一件事。全页只把力气放在一件事上，其余保持安静。进入动画全页只编排一次，不要每一段都从下面淡入。序号、箭头和点号分隔只有在内容真的是步骤或清单时才用。

圆角、阴影、描边全页各一种，写进色板旁边。卡片不是默认都加同一圈浅阴影。

## 首页篇幅

首页从上到下分层。一层是一个完整区域，先写层序，再写样式。第 1 层是导航，最后一层是页脚。首页不少于 9 层，所以导航和页脚之间至少还有 7 层内容。可以多于 9 层，页脚仍然是最后一层。层和层怎么接，对照模板表里这次打开的链接，以及 [web-prototype 的段落骨架](https://github.com/nexu-io/open-design/blob/main/design-templates/web-prototype/references/layouts.md)。

配方里按这个顺序编号：

1. 导航。能看出当前页。可以压在下一层上面，仍然单独算第 1 层。
2. 往下每一层换一种布局，也换内容的分量。紧挨导航的那一层接近一整屏，并且过「设计完成度」：大标题、一句说明、一个主动作、一张大图。图至少占这一层的一半。若是左右对开，两栏底边对齐，字的一侧不留下空底。
3. 再往下的层可以是一排入口、两三列说明、一组事实或一张大图。相邻层不重复同一种布局。不要每一层都是「标题加两行字」。
4. 规范要求出现的城市、行业、搜索、费用和文章入口都落在这些层里。数量多的入口分出层次：三五个重点用大图，其余用小图或文字行，链到自己的页。
5. 页脚的上一层是收束：下一步是什么，链到搜索、费用或下一篇真正存在的页。页脚自己是最后一层，不把收束并进页脚。

规范里的块不够排满 9 层，或多数块只有一两句时，仍然做满 9 层。缺的层用「补材料」补，不靠把字号放大或把留白拉到没有内容。窄屏层序不变，只是每层改成上下堆叠。

## 补材料

规范规定了主题和禁止项，但句子不够把首页做成一长页时，按规范里已经点名的题材上网找材料。找的是这一块本来就该讲的事，不是另起一个栏目。

可以补的：这座城的街道、建筑和季节事实；这门手艺在现场怎么进行、量什么、哪里该停手；公开页面上已有的说明。图按「配图」另找。每段补上的句子在配方里写下来源名称和地址。

不可以补的：规范没给的公司、电话、税号、地址、价格、评价、人数和合作品牌。规范写明不做的流程，例如询价、派单、申请步骤，也不要用网上的材料写进来。找不到可靠来源的那一块，保留规范里的原句，不写空话凑长度。

## 配图

某一段需要图，用户没有给文件时，自己上网找符合这一段题材的图。城市找这座城的街道或建筑，工种找这门手艺的现场，菜、房间、产品各找各的。地标、绘画、拼贴、操场、车站和球场，只有这一节就是在讲它们时才用。

1. 下载进站点的图片目录，页面只引用站内地址。
2. 图注写来源。知道作者或许可就写上。图注用辅助字号，不写成第二段正文。
3. 按「裁切」写明比例、焦点和替代文本。替代文本说画面里有什么。
4. 同一题材可以重复使用同一张，换一个题材就另找。

人物、员工、客户和合作品牌仍然只用用户提供的真实照片和标识。找不到合适的图时，按该布局的缺图做法收成文字或色底，并在配方的图片策略里写明没找到。

规范指定了图库，或禁止某一类图时，听规范。规范只要求放在站内并署名时，把找到的图存进站内即可。风格条目里「没有原片就不建组」指的是用户要展示自己的作品。页面是在说明一个地方、一门手艺或一件产品时，仍然按上面的步骤去找图。

## 背景

页面底和某一层的表面，不要只填一个纯色。按主风格和这一页的题材，上网再找背景素材：纸纹、颗粒、石材、木材、灰泥、织物，或一张能铺在层底的现场照片。找的是表面，不是另一张内容图。

1. 下载进站点图片目录，页面只引用站内地址。配方里写来源。
2. 平铺的纹理要看不出接缝。照片做层底时按「裁切」放进画框，文字放在实色块或遮罩上。
3. 一页只用一套背景家族。首屏或一个满幅层可以再加一张现场照片。不要给相邻几层各换一张无关的背景图。
4. 纹理只轻轻改变明暗，不改掉颜色角色。正文、按钮和表单的对比仍然够。
5. 找不到合适的素材时，这一页写明用纯色，不用程序生成的杂点冒充纸或石材。

## 裁切

先定画框，再放照片。画框用 `aspect-ratio` 写死。图在框里用 `object-fit: cover`。不要把画框改回 `auto`，也不要让原图像素的宽高决定卡片高低。

一页里每种角色只有一个比例：

| 角色 | 比例 |
|------|------|
| 首屏主图 | 4:5 或 16:9，全页只选一个 |
| 卡片图 | 3:2 或 4:3，同一组只选一个 |
| 文中插图 | 3:2 |
| 头像 | 1:1 |

`object-position` 对准画面里要留下的东西：门面、街道、工具、菜。主体在画面边缘时不要用默认的正中，否则裁完只剩天空或地面。裁切会切掉图注里点名的主体时，换焦点或换一张图。

同一行的图框等高、同宽。来源是竖图或横图都裁进这个框，不拉变形。图注不进入画框的高度。加载前框的尺寸已经在，图来了不把按钮顶走。

首页要列出很多入口时，分出层次：少数几张用首屏或卡片的大比例，其余用同一套小比例，或改成文字行。不要十几张同样的大图配上同样长的说明。这一页的布局若是画廊，才可以整页都是大图。

## 弹层和选择

下拉、单选、多选、筛选、日期和弹出层都自己写外观，跟当前主风格一致。不用浏览器或系统自带的菜单、对话框和选择框。

- 选择：按钮上显示当前值。展开的是页面里的列表。选项有悬停、当前和焦点。上下键移动，回车选定，Esc 关上。
- 单选和多选：自己画标记，文字标签可点。选中有文字或标记，不只靠颜色。
- 弹层：自己的面板，有标题和关闭。焦点留在层内。Esc 和关闭都能退出，退出后焦点回到打开它的控件。不用 `alert`、`confirm`、`prompt`。
- 窄屏上的筛选层同样自己写，能关掉。

输入框和按钮的边、底色、圆角也按主风格写。语义用按钮、列表和对话框角色，方便键盘和读屏。外观不交给系统。

## 实现

选定 id 之后，按 [references/implement.md](references/implement.md) 里对应的节做。那里写了时间线、滚动、指针、黏连、渐变模糊、金属边，以及离开页面时要停掉什么。

- 悬停、焦点、颜色和简单显隐用 CSS。
- 跟滚动进度绑在一起的动画只用一套：CSS scroll-driven animations，或一个 JavaScript 时间线库。同一属性不能两套一起改。
- 全站平滑滚动最多一个实现，卸载时销毁。
- WebGL 最多一块画布，只服务于那个高成本特效。限制像素比，离开屏幕或页面隐藏时停止渲染，失败时换成静态图。
- 逐词动画保留一份不拆开的文本给辅助技术。链接和按钮里的文字不拆。
- `prefers-reduced-motion: reduce` 时不做滚动擦洗、循环和视差，直接显示终态。

## 性能

用户要测速、排查慢页面，或页面做完需要验收时才跑完整测量。只要求选风格时不必先审计，但配方里的性能预算仍然要遵守。

指标阈值和浏览器接口会变。引用具体数字前先核对：

- Core Web Vitals：`https://web.dev/articles/vitals`
- 性能面板：`https://developer.chrome.com/docs/devtools/performance`
- Lighthouse 计分：`https://developer.chrome.com/docs/lighthouse/performance/performance-scoring`

先确认有哪些浏览器或性能工具。有追踪就用追踪；没有就做源码和网络分析，并写明哪些指标没测到。只有用户明确要求时才安装或修改浏览器调试工具。需要 Chrome DevTools MCP 时使用当前的 `chrome-devtools-mcp`：

```json
"chrome-devtools": {
  "command": "npx",
  "args": ["-y", "chrome-devtools-mcp@latest"]
}
```

测量顺序：

```
进度：
- [ ] 冷加载追踪
- [ ] 核心指标与成因
- [ ] 网络与资源
- [ ] 构建与源码（读不到仓库就跳过）
```

1. 打开目标地址，做一次带刷新的冷加载。追踪为空时，先确认页面已经打开。
2. 拆开 LCP（响应、资源、渲染延迟）、CLS 的移位元素、渲染阻塞和关键请求链。工具返回的 insight 名称对不上时，先列出这次实际有的名称。
3. 检查脚本和样式是否堵在头部、关键字体和主图有没有提前声明、缓存头是否过弱、体积是否过大、预连接的源是否真的有请求。
4. 用户抱怨点击发顿时再测输入延迟。
5. 读得到仓库时，再看打包器、拆包、图片、字体、压缩和是否把 source map 打进生产包。读不到仓库就停在测量和建议。

连上 Chrome DevTools MCP 时：`navigate_page` 打开页面，`performance_start_trace`（`autoStop: true`，`reload: true`）做冷加载，`performance_analyze_insight` 拆指标，`list_network_requests` 与 `get_network_request` 看请求。

实验室里常见分档如下，正式评级以当场查到的文档为准。

| 指标 | 好 | 待改进 | 差 |
|------|----|--------|----|
| TTFB | < 800ms | < 1.8s | ≥ 1.8s |
| FCP | < 1.8s | < 3s | ≥ 3s |
| LCP | < 2.5s | < 4s | ≥ 4s |
| INP | < 200ms | < 500ms | ≥ 500ms |
| TBT | < 200ms | < 600ms | ≥ 600ms |
| CLS | < 0.1 | < 0.25 | ≥ 0.25 |
| Speed Index | < 3.4s | < 5.8s | ≥ 5.8s |

用请求、DOM 或代码核实后再下结论。收益为 0 的只记录，不列入待办。建议要落到文件或选择器。

审计报告按这个顺序：指标表、按收益排序的问题、可执行改法、源码结论（没有仓库就省略）、没测到的部分。

## 不要

- 不要把默认配方或「混搭」当成随机结果。主风格不要沿用默认表，也不要因为这页像杂志、像店铺就重复上一次的风格。
- 不要一次用两套主风格，或让相邻两段使用同一个布局。
- 不要编造客户、评价、价格、日期、人数或合作品牌。
- 不要让特效或动画挡住正文、按钮和表单。
- 不要在减少动效时只把动画加快，要直接给出终态。
- 不要用布局的示例题材补页。规范没写的职位、404、订阅、预约，不要出现在别的页面上。
- 不要用线稿或色块冒充这一段需要的照片。需要图就按「配图」去网上找，存进站点并署名。
- 不要只用一块纯色当整页背景。背景按「背景」上网找纹理或表面，存进站点并署名。文字仍放在实色块或遮罩上。
- 不要按原图的宽高排版，也不要把画框设成自动高度。裁切按「裁切」里的比例和焦点。
- 不要用浏览器默认的标题大小、默认间距和系统控件来充当设计。字号、间距、颜色角色和控件按「页面标准」写。
- 不要用系统默认的下拉、单选、多选、日期和弹窗。这些按「弹层和选择」自己写。
- 不要停在首页。规范列出的页一次做完，或写明省略原因。全站用同一套主风格。
- 不要让首页少于 9 层。第 1 层是导航，最后一层是页脚。规范句子不够时按「补材料」上网找，不编规范禁止的数字和流程。
- 不要交一版没有设计稿的页面。左右对开必须底边对齐。标题不要只强调一个词。全页不要每段都淡入。

## 交稿前检查

- 配方里的 id 都能在目录里找到，细化里的字号、热区和缺内容做法已经落到页面上。
- 有成文规范时，内容清单里的每一页都在，省略的页写了规范允许的原因，全站是同一套主风格。页面上没有规范没写的题材，空状态说的是这一页自己的事。
- 需要图的块有图，文件在站点图片目录里，带宽高、替代文本和来源。同一角色的画框比例相同，焦点留住主体。没有拿图冒充客户、员工或合作品牌。
- 背景用了网上找到的纹理或表面，文件在站点里，写了来源。文字在实色块或遮罩上，对比够。整页只用纯色时，配方里写了「纯色」。
- 本页必须有的九项都在。字号不超过五档，间距是 8 的倍数，节距大于节内距。控件同一高度。第一屏只有一个主动作。
- 首页从导航到页脚不少于 9 层，配方里逐层编号。紧挨导航的那一层接近一整屏，两栏若对开则底边对齐。设计稿写了色值、字体和这一页唯一记住的一件事。配方里有这次打开的模板链接。上网补的材料写了来源，且没有规范禁止的公司、价格、评价和流程。
- 下拉、单选、多选和弹层是自己写的外观。键盘能打开、选定和关闭，焦点看得见。
- 键盘能走完导航、按钮、表单和打开的面板，焦点看得见。
- 窄屏多栏已改成上下堆叠，阅读顺序与桌面从左到右、从上到下一致。
- 关掉 JavaScript 和动效后，第一帧仍然能读完标题、说明和主动作。
- 主风格写了种子、下标和抽中的 id，并且不是上一轮或本站已经用过的那个。用户点名了风格 id 时，用用户点的那个。
